# 证据边界与接入说明

2026-10-12，AI 参与改编。这里是通用试用约定，正式 EU、Gate0、Registry 和坐标 schema 尚未提供；本包不会据此宣称完成整套系统。

## 原件、转写、推论分别保存

原始 PDF 是 L0，不改字节、不覆盖。记录完整 SHA256；聊天来源则保留原始记录与来源时间。解析原文、页级 JSON、布局坐标、图像和引擎/模型版本是可重建的 L1。忠实转写叫 `document.md`，精读或整理稿才叫 `reading.md`。修正、翻译、LLM 清洗另存版本，并记录具体改动。

检索命中、摘要、引用图谱和模型回答先作候选线索。正式证据需要回到原件核对逐字引文、物理页及定位；物理 PDF 页从 1 起算，印刷页码另存。缺失页号或 bbox 时如实标记，不能由段落顺序补造。bbox 必须说明坐标单位、原点和所属原件。逐页映射不等于每个 Markdown 字符的坐标映射。

`compiler_quote_verified` 表示对当前编译输入的逐字核对，`l0_verified` 表示回到原始文件的定位核对；二者不可互相代替。DOI、文献身份、格式或脚本校验通过都不证明 claim 得到支持。示例 [evidence-candidate.json](examples/evidence-candidate.json) 是空白候选模板，两个核验字段默认 false；它不是朋友已确认的正式 EU schema。

## 三层职责

| 层 | 本包提供 | 接回原系统仍需什么 |
| --- | --- | --- |
| 共享 Evidence Space | 搜索候选、原件转写、元数据/来源、候选 claim ledger | Gateway 身份分配、Registry、EU 编译与独立核验接口 |
| Scientific Coordinate Atlas | 保留方法、观察、机制、边界等分析字段 | 正式概念表、M/G 及演化规则、坐标更新实现 |
| Research Process | 假设、竞争解释、负对照、综述、批判与复核 | 任务状态、执行与反馈、项目级权限及持久化 |

Science Dog 可以使用 `academic-hypotheses` 提出候选；Review Dog 可以使用综述、批判性阅读和审查技能挑战它。双方读写约定的共享材料，不相互发送指令，也不把自己刚生成的回答在同一轮自行认证为证据。

## 身份、来源与运行

传入既有 `source_id` 和 Zotero key，不伪造正式 `P#########`，不由研究技能改 Registry、移动 Canonical Object 或评定 Utility。DOI、年份、作者、期刊等不知道就留 null。同一研究、多版本或同源摘要标记同一 source_family，不能算多个独立支持。

沿用用户已有工具和模型渠道。云端解析、embedding 或 LLM 需要实际后端及对应使用授权；技能安装本身不会上传 PDF、购买额度或启动解析。凭据只在用户环境/密钥配置里，不能放进材料或 Git。未知远端任务先查原任务，不自动重发。新任务写新输出目录，留下原始返回及失败记录。

## 接入顺序

先用一份真实 PDF 跑通“原件 → 转写 → 回到原件抽查”，再试检索和来源去重，最后用已核对材料做假设/综述/审查。取得原工程 schema 后才做正式 EU、Registry 和坐标接口适配。每一步报告实际完成、待复核和未执行的检查；缺少后端时仍可使用离线模板与方法技能。
