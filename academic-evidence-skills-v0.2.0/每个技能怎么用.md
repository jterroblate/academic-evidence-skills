# 每个技能怎么用

版本：`academic-evidence-skills-v0.2.0` · 2026-10-12 · AI 参与整理。

本新版共 **16项技能**：原14项加上 `academic-langextract` 和 `academic-claim-search-quality`。AskChem 源码与讲解图是配套参考资料，不计作第17项技能。这里合并的是方法、技能文件及参考资源；安装不代表正式 Compiler、Registry、评测 runner、索引后端或真实模型/provider 已接入或已运行。

以下提示词可直接给具有文件和命令权限的 agent。`$技能名` 用于 Codex；Claude Code 可改成 `/技能名`。将输入路径、研究问题及新输出目录换成实际内容。仅安装技能文件不等于安装它所调用的程序。

使用用户指定的材料、现有配置和已授权执行渠道；未配置时先交准备报告或方法计划。不得从上游示例自动选模型、切 provider、开云服务、改线上索引或扩大访问范围。下表所有用法路径均相对于本包根目录。

## 常见选择

PDF 三个技能有不同分工：Docling/MinerU 是解析渠道，pdf-to-markdown 整理标准交付；按已有渠道选择即可。几个检索技能也可以择一使用，只有实际覆盖不足时再补源。同一篇论文的多路命中不会增加独立证据数量。

`academic-citations` 校验文献身份；`academic-critical-reading` 检查内容；`academic-peer-review` 审查 claim 链；三者的通过含义不同。假设技能的产物始终是待检验解释。Evidence Space、坐标和研究过程的分工见 [接入说明](证据边界与接入说明.md)。


## 新增技能怎么接入现有流程

`academic-langextract` 放在“已有 PDF 解析产物之后、候选主张审查之前”。它接收已有 L1 文本，不负责 PDF 解析或重编译。`academic-claim-search-quality` 放在“已有 claim 检索之后”，检查检索是否找全、排对、保留反例与正确过滤；没有运行接口时仍可整理评测计划。两者均不代替文献身份、原件定位、entailment 或科学可信度的独立检查。

### academic-langextract：把已有文本变成可审查候选

至少提供只读 L1 文本、外部 Source ID、L1 hash/版本、原件 L0 hash/位置、已有页/块映射、新输出目录和本次已授权的模型配置。身份、hash、映射或配置缺失时明确列出缺口，不自行补 ID 或假造定位。SDK 安装只是准备；没有已授权渠道时返回 `needs_review` 与“待配置”。

输出包括完整候选、失败及零候选原因，实际输入和原始模型响应位置，以及各候选的独立检查。`quote` 是连续逐字引文，`claim_paraphrase` 是改述；主客体、数值字符串、单位、比较符、否定与作用域、条件、群体/时间、范围及不确定性不得在拆分中丢失。没有明示的字段留空。

L1 字面匹配、L0 原件定位与 entailment 分别记录。需独立重算 `raw_input[start:end] == quote`，不能把 SDK 的 token 对齐、fuzzy/lesser、非空 span 或模型自行报告的通过状态当字面验证。重复引文无法唯一定位时保持 `needs_review`；缺映射或未核对原件时定位为 `unknown`。即使字面匹配通过，产物仍是 `candidate`/`needs_review`，不创建 FormalEU、不写 Registry，也不评定科学重要性或坐标。

调用层须能保留完整原始响应、每次 attempt、实际输入、模型/SDK/prompt/schema 版本及重试配置；annotation 文件不能替代完整原始响应。接口未提供原始响应时先报告审计缺口。已知返回只修本地保存、解析和检查；远端结果未知时保留状态并观察原任务，不盲目重发。

可复制提示词：

```text
使用 $academic-langextract，处理我指定的既有 L1 文本。
Source ID、原件/L1 hash 与版本、页/块映射、输出位置、已授权模型渠道均从本次工程输入透传；缺少时明确列出，不自行注册或切换 provider。
先确认当前调用封装能保留完整原始响应，并核对 LangExtract/provider/SDK/外层任务的重试。
按任务所需类型抽取候选，quote 与改述分开。保留原主客体、数值字符串、单位、比较符、否定作用域、条件、群体/时间、范围和不确定性；没有明示的字段留空。
逐条独立检查真实 L1 的 raw_input[start:end] == quote，并记录重复匹配、fuzzy/lesser、失败和零候选，不筛掉失败项。
分别返回 L1 引文检查、L0 定位检查与 entailment 审查状态；缺映射或未核对就 unknown。所有候选仍是 candidate/needs_review，不创建 FormalEU 或写 Registry。
已知返回只修本地；未知远端不盲目重发。交付完整候选/失败清单、实际检查和原始响应位置，说明尚未验证的部分。
```

详细步骤与非正式候选示例见 [academic-langextract 用法](skills/academic-langextract/references/usage.md)。示例不是正式 EU schema，也不是真实模型运行结果。

### academic-claim-search-quality：检查已有检索是否好用

提供任务目标、现有语料/索引快照或保存的检索返回、已有 `source_id`/`claim_id`/source-family、原文定位、查询与筛选范围。AI 从材料中提取参数和版本，不知道的留空；评价前固定返回单位、K、相关性标签、去重和过滤规则。金标需覆盖同条件反例、条件错配、否定、数值差异、同源重复与 insufficient，自动标签先作候选；开发与 held-out 按来源族隔离。相关性标注与支持/反驳判断分开。

可交 `evaluation-plan.md`、版本化金标或标注候选、逐查询结果/失败记录与 `quality-report.md`。有实际渠道和标注才报告 Recall@K、nDCG、反例命中、来源族重复与过滤漏出；无运行渠道时交计划，无 embedding 时写 `lexical-only`，仅分析保存返回时写“离线结果评测”。缺标注、时序或后台运行证据时不补造得分、耗时或 run ID。

优先理解并裁剪 AskChem 已有 SQLite/FAISS + FTS5 实现；只有用户已选择 Qdrant 才按症状读它的上游参考。引用参考资源不授权部署、迁移存储、更换 embedding、购买模型或改线上索引。先在开发集改进，再在固定 held-out 复核；小样本增益与不确定性一起报告。ANN 对 exact KNN 的召回和对人工金标的相关性是两种检查，均不等于 claim 支持准确率。

检索相关性、quote/原件定位、entailment 与科学可信度保持分开。排序分数、引用量、模型 confidence 或生成 graph 不赋值为 Utility、科学重要性或 scientific coordinate；不分配正式身份、不写 Registry/Gateway、不晋级 FormalEU。

可复制提示词：

```text
使用 $academic-claim-search-quality。读取我指定的 claim 语料快照、已有 source_id/claim_id/source-family、查询与现有检索返回。
先提取版本与过滤范围，固定评价单位、K、gain、去重规则；建立可审查的金标候选，覆盖反例、条件错配、否定、数值、同源重复和 insufficient。
把相关性与支持方向分开；按来源族隔离开发与 held-out，不用检索排序/分数定义金标。
只有已配置且已授权的通道才参与比较；没有 embedding 时明确 lexical-only，没有运行入口时明确 plan-only，只评保存返回时说明离线范围。
有实际标注与执行证据才报告 Recall@K、nDCG、反例、重复、过滤和成本；缺项留空，不编造指标或运行记录。每个失败读原文语境，再提出最少必要的工程改进与 held-out 复核。
优先裁剪 AskChem 现有 SQLite/FAISS/FTS5；未选择 Qdrant 时不用它的排障子树。不要部署新服务、切模型、改线上索引或晋升生成 graph。
区分检索相关性、原文定位、entailment 与科学可信度，交付实际完成、原始返回位置、失败和未执行项。
```

详细的分阶段计划、指标口径与状态见 [academic-claim-search-quality 用法](skills/academic-claim-search-quality/references/usage.md)。这些约定是方法说明，不是已实现的评测 runner 或后端接口。
