# 输出合同与验收含义

schema 是本次独立转换包的接口，尚未与朋友原工程确认。这里的 bundle 是一次转换的交付目录，不是 Canonical Object，也不分配 Source ID。

| 文件 | 用途 | 不能据此宣称 |
| --- | --- | --- |
| `source.pdf` | 输入 PDF 字节副本及 L0 回溯锚点 | 文献科学结论真实；原文件的 PDF metadata 已确证 |
| `document.md` | 逐页全文转写，带物理页锚点 | 已完成深度精读；已与 L0 逐字核验 |
| `parser/pages.jsonl` | 保留逐页原始解析 Markdown | 解析错误已被消除 |
| `parser/layout.json` | 记录从 PDF 取得的原生文字块与 bbox、PDF metadata | 这些块与 Markdown 每个字已有精确一一映射 |
| `page-map.json` | document.md 页段行号、物理页及 page label | 印刷页码等于物理页；外部解析方的页归属已经独立验真 |
| `metadata.json` | 透传既有文献信息，未知留 null | 身份已登记、DOI 去重已完成 |
| `conversion.json` | 来源哈希、引擎/版本/参数、覆盖页及产物哈希 | 通过哈希就能证明语义保真 |
| `quality.json` | 机器结构和完整性检查、待复核问题 | 表格、公式、数字、阅读顺序全部正确 |
| `assets/` | 解析输出的本地图片 | 已解释图片内证据或 OCR 内容 |

## 状态

- `complete`：请求为全篇，机器检测未发现当前规则能识别的待复核问题。
- `partial`：用户明确选择页子集，所选范围完成；coverage 仍记录原 PDF 总页数。
- `needs_review`：存在空/低文本页、疑似多栏、加工方式未知或其他已知问题。即便机器检查目录完整，也不能交付为正文完全成功；缺图和非法输入则会明确失败。低文本和多栏检测是保守启发式，可能误报短标题页，也不能发现所有扫描或复杂布局。

状态表示工程交付和检查结果，不表示论文内容可信度。`quote_verified`、`l0_verified` 和 EU 就绪状态不得由转换脚本自动转正。

## 版本与失败

已有输出目录拒绝覆盖；新的转换使用新的目录。脚本在临时目录写完后再发布 bundle；输入、依赖或结构错误要明确返回失败。`needs_review` 可以保留诊断包和原解析结果，供下一步补 OCR/复核；不要只删除它再把相同任务反复发给远端。

转换返回 `0` 为机器范围内的可检查交付，`3` 为带问题的诊断交付，`1/2` 为失败。`verify.py` 的 `0` 表示结构/哈希/映射检查通过（允许已声明的 partial）；`3` 表示待复核；`1` 表示产物被篡改或结构损坏。

远端后端的 task ID、原始 JSON、模型版本等材料应在适配输入或外部解析档案中保留。机器运行时间、源码版本及哈希为回放线索，不承诺不同硬件和依赖环境逐字节重现同一解析结果。

## 引文如何下探

先用 Markdown 行号找到页段，再用物理页号回到 source.pdf。如需 bbox，必须阅读对应原始布局信息并核对坐标基准与阅读顺序。本包只自动提供页级映射；精确 quote 校验、locator confidence 与 Formal EU 编译仍是独立工作。
